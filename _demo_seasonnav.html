Season navigation on the card , two options

Item 23, demo only. Both options call the same existing function, switchSeason(card_id). Neither is new capability: the season list is already fetched, already rendered, and already switchable behind "View all 7 seasons".

The axis is free, and that is the whole reason this is cheap. Horizontal is already taken , swipe and ← → walk the list you arrived from (rankings, compare, search), via seqGo. ↑ and ↓ are bound to nothing. So the model reads in one sentence: horizontal walks the list you came from, vertical walks this player's own seasons.

AND THE PANEL STAYS, WHICH IS WHAT MAKES THE GESTURE SAFE TO ADD. "View all 7 seasons" is already visible, already labelled, and already says how many there are, so discoverability is solved before the swipe exists. The panel is where the swipe gets taught , a reader who opens it once has learned that seasons are a dimension of this card, and the peek edge then reads as what it is. That is the honest answer to "an undiscoverable swipe is not a feature": the gesture does not have to carry its own affordance, because the control beside it already does. It is pure addition, and it replaces nothing.

What it buys

One mental model, two axes, and it works identically on phone and desktop. The peek is the affordance: a stack you can see before you know the gesture, which is the same trick the horizontal .peek already uses.

What it costs

It takes the page's scroll gesture on the card. Today card.html:2608 locks to 'y' and means "this is a scroll, leave it alone". Taking that axis means the most prominent element on the page is no longer draggable to scroll. Normal in a card stack, jarring in a document, and the card is currently a document.

Mitigated by reusing the existing floors , LOCK_PX 12, DIST 48, SLOW 800 , so a slow drag still scrolls and only a flick pages. The demo uses the same numbers.

Option 3 , NOT SHIPPING. Kept so the reasoning survives.

Chips were solving discoverability, and the panel already solves it. A permanently visible chip row under every card is a SECOND control for a function that has a discoverable one, which is furniture rather than affordance , and it was the only option that REPLACED something. Left here because it is a real alternative and the next person to ask "why not chips" deserves the answer rather than the conclusion.

What it buys

No discoverability problem exists. Lucas's own note is that an undiscoverable swipe is not a feature; this has nothing to discover. It also shows the shape of the career at a glance, scores included, which the gesture cannot do without being used.

What it costs

It is furniture. It adds a permanent row under the card on every card, and it breaks the symmetry that makes option 1 attractive , seasons become a control while the arrival list stays a gesture. It also replaces, rather than shortcuts, the existing "View all 7 seasons" button.

Note it is horizontally scrollable, so it borrows the axis option 1 avoids taking, but inside its own element where there is no ambiguity.

Desktop , the same in both options

Arrow keys plus a position indicator that is itself the control. No vertical chevrons: the card already carries horizontal ones and a second pair turns it into a D-pad.
