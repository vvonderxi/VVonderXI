## 5. RULES YOU MUST NOT REDISCOVER THE HARD WAY

The full set is `CLAUDE.md` §C, with the evidence in `SILENT_FAILURES.md`. **Open `SILENT_FAILURES.md` when a change "does nothing", when a measurement disagrees with what you can see, or when a query returns a suspiciously round number.** These are the ones this week added or proved.

- **"NOT IN THE REPO" IS NOT "NOT LEAKED".** The API-Football key IS exposed and rotation IS required, yet every repo-side check is clean and always will be: not in HEAD, not in git history (`git log --all -S` returns 0), never in any HTML, `.env` gitignored and untracked. **The exposure was in a CHAT TRANSCRIPT and was never committed**, which is exactly why the searches came back empty and why the August 9th handover could not substantiate the claim it inherited and suggested the doc might be wrong. **A secret can escape through a transcript, a screenshot or a paste. Ask where a key was USED, not only where it was stored.** **OPERATIONAL CONSTRAINT: rotate only when NO BACKFILL IS RUNNING** , a rotation mid-run kills every in-flight request, and the enrichment scripts checkpoint per league-season, so a half-written run is the expensive failure.
- **`git commit --only <path>` COMMITS THE WORKING TREE, NOT THE INDEX**, silently discarding anything staged with `git hash-object` + `update-index`. Splitting two concerns that live in ONE file works only if the final `git commit` takes **no path argument**. This produced a wrong commit that had to be amended.
- **`git reset --hard` IS REPO-WIDE.** Use `git checkout -- <named files>`. And commit or stash unrelated work BEFORE a commit split, which is exactly when uncommitted work is most exposed.
- **THE INSTRUMENT NEEDS THE SAME SCEPTICISM AS THE CODE**, and it has now produced a false reading in four consecutive sessions. This week: `resize_window` left `innerWidth` at 1920 and `outerWidth` at 0, so any "390px" measurement taken that way would have been fiction (use same-origin **iframes**, which evaluate their own media queries); and the console reader returned "no messages" for a warning that had definitely fired, so its silence proved nothing (a deliberate probe caught it). Earlier: `pgrep -f <script>` matched its own shell, and a parser using `[A-Z]+` silently dropped `L1`. **Establish a positive control before believing a negative result.**
- **A VISUAL CHANGE IS NOT VERIFIED UNTIL RENDERED AND MEASURED IN A REAL BROWSER.** Serve with `python3 -m http.server` and measure. Reading the markup misses defects that layout exposes instantly.
- **AN ORPHAN `*/` SILENTLY EATS THE RULE THAT FOLLOWS IT.** A comment written `vvflip*/vvmono*` closed early and deleted `.vvflipwrap` from compare's stylesheet, so the card flip rendered with **no perspective at all** for an unknown length of time. **Count `/*` vs `*/` and verify surviving `cssRules`, not the source.** This has now happened twice, and cost 42 of 45 rules in `card.html` the first time.
- **`vv-core.js` CACHE TOKEN IS MANUAL.** Bump `?v=` in card.html, compare.html and rankings.html whenever vv-core.js changes. **Current value: `?v=20260820b`.** Forgetting makes any vv-core change silently no-op while looking fine.
- **THE MATVIEW'S COLUMN LIST IS FROZEN.** Appending a column to `player_card_view` surfaces it NOWHERE; it needs a DROP+CREATE (or the 2026-08-19 rename-swap) plus its 8 indexes. Always `REFRESH MATERIALIZED VIEW player_card_mv` after any data or view change.
- **Write on `api_player_id`, never on a display name.** Names are not unique and the collisions are position-changing.
- **No em-dashes or en-dashes anywhere.** Spaced commas. `NR` for missing data, never 0.
